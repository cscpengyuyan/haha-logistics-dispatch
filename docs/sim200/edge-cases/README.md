**T39**：对目标仓计算低、基准、高需求的补货建议 1 / 3 / 5 台。基准 3 台逐台从真实库存 API 入账，通过 D 前置申请、不同主管批准、发送、目的仓验收。未批准发送和同人批准实际被拒。批准和在途阶段目标仓可发库存未增加；每次实收后增加一台，最终 3 台、剩余建议为零。没有将建议直接写为库存。此证据覆盖业务审批及实物链，不证明包含资金占用、滞留成本的综合测算界面。

**T42**：两台需求对应原计划 SN 094-01 / 094-02，另一个替代候选有明确的同批海运来源。三台预报中原 094-01 实际短少，另两台实收，其中替代候选货损被强制隔离。系统实际拒绝货损直接可发入库、短少 SN 预留、隔离 SN 预留。仓库复检释放并记录换配授权后，按正常采购、签发、验放、逐台 POD 和结算流程完成两台交付。原短少 SN 没有出现在实物表，原海运清单 receipt 仍为空；原差异及换配依据保留。

共 59 条实际轨迹、9 次预期拒绝。最终实物为 3 台目标仓可发 + 2 台交付，与 3 台初始源库存 + 2 台海运实际实收守恒。三个预报 SN 不等于三台实物入账。
