# HAHA Logistics V8

美国物流调度工作台：围绕订单、库存、预约、时区与放行条件组织完整工作流。

- [打开 V8 工作台](https://cscpengyuyan.github.io/haha-logistics-dispatch/v8/)
- 原 `/v7/` 地址自动进入 V8，保留查询参数与页面锚点。
- [V7 归档](https://cscpengyuyan.github.io/haha-logistics-dispatch/v7/legacy.html)
- [协作后端部署与接口说明](server/README.md)

## V8 更新

1. 16 个模块统一蓝白工作台样式，分组导航、可访问搜索与手机抽屉。
2. 全局搜索展示多结果，支持客户、城市、ZIP、组合词、键盘选择与完整结果。
3. 调度页按「选择订单 → 生成预排 → 放行前校验 → 保存批次」推进，主操作固定可见。
4. 出发仓区域与全国仓网切换，订单卡显示中文服务与缺项直达入口。
5. 完整恢复里程、速度、装车、缓冲、休息、筛选及地图视图；导入后使旧计划失效。
6. 手机调度三视图与底部「查看计划」，订单列表转换为卡片。
7. V8 独立本机工作区；首次读取兼容 V7 数据。导入、拉取与重置前保留恢复点。
8. 新增显式协作连接、版本冲突保护与服务端审计界面；令牌只保存在页面内存。
9. 修复底图设置未读取实际输入框的问题。
10. 提供可部署的 Node.js + SQLite 内部协作基础服务。

## 运行

前端没有构建和 npm 依赖。使用任意静态 HTTP 服务托管 `v8/`，或通过上方 GitHub Pages 访问。

后端需要 Node.js 24.22+ 与持久磁盘。账号、CORS、HTTPS、备份及运行方法见 [server/README.md](server/README.md)。GitHub Pages 只运行静态前端，仓库的 Node 后端不会随页面发布自动运行。

## 验证

在仓库根目录运行：

```bash
npm test
```

目前包含 35 项检查：搜索 5 项、调度 10 项、工作区恢复/隔离 6 项、真实 HTTP 与 SQLite 集成 14 项。浏览器人工复核覆盖桌面预排、多结果搜索、参数保存后完整刷新、设置页、390px 手机订单卡片与计划切换。

原四张示例订单仍计算为 4 站、约 183.2 km、8h 42m、$926.29。算法与库存、供应商、预约、版本放行约束继续保留。

## 当前能力范围

页面使用合成业务数据。线路是估算连接，金额是情景估算。客户/司机页面仍为演示视角；真实短信、货车道路、附件存储和订单级授权尚未连接。可部署的共享工作区后端面向受信管理员/调度员，不能替代完整生产 TMS 权限系统。

V8 数据存储键是 `haha-v8`，V7 使用 `haha-v7`。回到旧版不会自动同步 V8 中的更改；可通过备份管理数据。
