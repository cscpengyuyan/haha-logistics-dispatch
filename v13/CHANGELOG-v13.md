| 项目 | 变化 |

同时修掉两个原有视觉缺陷：
- 待办页两条跳转链接直接 `prepend` 到内容区，渲染成行内下划线文字并与统计卡重叠 → 改为 `.quick-links` 胶囊按钮行；
- 按钮全局样式只作用于绘制层（颜色/圆角/字体），不再覆盖 `display/gap/white-space`，避免地图订单池等复合按钮被压成一行截断。

### 2. 海运计划看板（重写 `ocean-desk.js` + 新增 `ocean-board.css`）

原实现：一张 5 列表格 + 两行 4px 内联色条，没有刻度、没有汇总、没有对比。

新实现：**以甘特图为主体的看板**

```
┌ 筛选（全部/待收/超期/有改约）· 目的仓 · 搜索 · 导出 ────────────────┐
├ KPI：航次 / 待收台数 / 超期未收 / 改约待办 ───────────────────────┤
├ 到仓甘特（周/日刻度切换）                        │ 到仓周负荷        │
│  SIM-SHA-HOU-02  ═══════ 航次汇总条  [超期7天]   │ 排期健康度        │
│    订舱与截关   ◆截单 ◆截关                      │ 改约待办          │
│    海上运输     ███████ 24 天                    │                   │
│    内陆派送           ▨ 1 天                     │                   │
│    到仓确认        ○╌╌● 冻结 vs 预测            │                   │
├──────────────────────────────────────────────────┴───────────────────┤
```

关键点：
- **按航次分组**，每组 4 条泳道：订舱与截关（里程碑菱形）、海上运输、内陆派送（斜纹段）、到仓确认；
- **冻结 vs 预测**：冻结到仓为空心圈，预测到仓为实心绿圈，两者不一致时用琥珀虚线连出偏差，左侧写明 `冻结 10/23 · 预测 10/25 · +48h`；
- **时间轴**：周刻度（MM/DD）与日刻度（每 4 天标注）两档，网格线对齐表头，荧光绿竖线为"今日"；
- **窗口自适应**：自动纳入截单/截关等最早节点；有超期批次时把时间窗延伸到今天，让"超期"在图上可见；
- **航次汇总条**：整段 截单→到仓 的浅色条，右端紧跟状态胶囊（超期 7 天 / 距到仓 3 天 / 已收清）；
- **右侧三块**：到仓周负荷（周一起算，含"同周多批到仓"提醒）、排期健康度（准点/延后/平均偏移）、改约待办（可点开对应航次）；
- **交互**：状态筛选（带计数）、目的仓下拉、关键字搜索（保持光标位置）、周/日刻度切换、点击航次整块跳转到下方单票跟踪、导出 CSV（新增柜号、装船、到港、延迟小时、已收台数、改约原因）；
- **空状态**：区分"无数据"与"筛选无结果"，后者给一键清空筛选；
- 保留原有 `Supply.sea` 单票船期跟踪与 `Resources` 历史交接，并对齐新配色（原计划灰 / 最新预计绿 / 实际回执蓝）。

### 3. 其他页面收益（无需改模块代码）
仪表盘、订单工作台、逐台库存、运输采购、经营复盘、地图调度、费用核对、仓口验放、预约短信等页面，全部通过 `theme.css` 获得新的卡片、表格、按钮、徽标与响应式表现；地图页订单池、复盘页指标块等模块自定义样式做了兼容性修补。

## 四、V13.1 追加：派单计划（按时间排车）

原「地图调度」只能手工挑票连线，没有时间维度。新增独立页面 **派单计划**（`#plan`，位于「调度中心」内、地图调度之前），把「时间 → 片区 → 车次」这层决策补上。

### 1. 数据层
- `engine/demo_seed.py` 追加 `seed_planning()`：同一出发仓（Dallas）在未来 7 天铺 18 票演练单，片区（ZIP 前三码）、订单类型（L1/L2/L3）、台数（1/3 台）、收货时段各不相同；原有 7 票保持不动且排在前面，不影响既有流程与测试。
- `demo-worker.js` 的 IndexedDB 库名升级为 `haha-logistics-public-v13-1`，让浏览器重新灌入新数据（会重置本机演练记录）。

### 2. 计划算法（`dispatch-plan.js`）
1. **取数**：只取 `status=ready`、非客户自提、有坐标的订单。
2. **按日分批**：用收货窗日期分组，支持 今天 / 明天 / 未来 7 天 / 未来 14 天。
3. **装车（容量约束）**：按收货窗先后做种子，逐票贪心插入，受车辆 `capacity_units` 与单车 10 小时班次上限约束；评分 = 超窗数×10000 + 时长 + 里程 + 类型混装 + 候场。
4. **站序**：先比较「时窗顺序」与「最近邻」，再做 2-opt 局部搜索，目标为「超窗数 → 里程」。演练数据上从 136 mi/1 站超窗 优化到 93 mi/0 超窗。
5. **出车时刻**：默认 08:00，若首站早到则后移（最多 5 小时），避免整段无效候场。
6. **运力匹配**：按台数挑车、按 ZIP 覆盖匹配班组；无覆盖时明确标「待指派 / 覆盖待核」。

### 3. 界面
- KPI：待排票数、待收台数、建议车次、超窗风险（车次超过车辆数时琥珀告警）。
- 左侧 **交付日轨道**：每日票数 / 台数 / 车次 / 超窗，条形长度＝当日台数，点击切换。
- 右侧 **车次卡**：`06:00–20:00` 行程带（收货窗琥珀条 + 车程序号点 + 绿色在途段）、车辆与班组、逐站「开工/离场/车程/窗内或超窗分钟」。
- 操作：**保存为草案**（写入 `/api/ops/routes`，随后出现在「地图调度 → 调出已存草案」）与 **去地图排线**（跳到 `#map?focus=<首站订单>`）。
- 与既有流程的关系：计划只产出草案与站序，签发仍走原单 F04 的 12 项校验，不改任何业务状态。

### 4. 改动文件
新增 `v13/dispatch-plan.js`、`v13/dispatch-plan.css`；修改 `v13/app.js`（注册 `plan` 页面与导航、可见角色）、`v13/index.html`（挂载资源）、`v13/engine/demo_seed.py`、`v13/demo-worker.js`。

## 五、V13.2 追加：地图调度改为「调度台」

原来的地图页是「订单池 / 地图 / 多站排线」三块平铺，配置表单与技术说明混在右侧窄栏里，调度员看不到"这一天有几车、每车几站、哪车该先走"。按美国尾程班次的实际用法重排：

### 版面
- **左：任务台** —— 订单池（可排 18 票，逐票显示里程/类型/窗口）+ **当日车次列表**（草案/已签、车辆、票台数，点一下调出）。
- **中：地图** —— 加高为 `56vh` 主视图，交付点、仓点、已选站序与在途线路都在这一屏。
- **右：车次执行卡** —— 站数/票台、里程、含作业等待时长、待复核数；逐站列表（上移/下移/锁站/移出/同停）；批次名称与交班备注；主按钮"保存排线草案"。
- **底部**：单票详情条 + 「核验与证据」抽屉（车辆班次、逐段承运依据、同范围费用试算、路网范围说明），默认收起。

### 功能
- 新增**当日车次列表**，直接显示已保存草案，点选即可调出（`loadRun`）。
- 订单池与车次列表各自滚动，不再互相挤压。
- 演练数据补 `location_precision=dock` 与 `coordinate_ref`，新单可直接「+ 排线」（可排订单 0 → 18）。
- 展开/收起订单池（原 `pool` 按钮）改到新容器仍可用。

### 实现方式
不重写业务逻辑：在 `dispatch-map.js` 中新增 `restructure()`，页面渲染后把既有 `data-box` 节点搬到新容器里，事件仍由原有 `data-act` 委托处理；新增 `runs()` 渲染车次列表与一个 `loadRun` 分支。样式集中在新增的 `v13/dispatch-shell.css`。

## 六、V13.3 追加：地图调度「按交付日」视图

原来地图页没有日期轴：`出发日期` 藏在「核验与证据」抽屉里，订单池把全部 25 票混在一起，调度员没法只看某一天。

### 界面
- 页首新增**交付日条**：`全部日期` + 未来 14 天逐日胶囊（周几 / 月-日 / 当日可排票数），周一切换处有分隔线区分「本周 / 下周」，右侧可打开原生日期选择器直接跳到任意一天。
- 选中某天时：胶囊转为深绿、KPI 四项（可排 / 在途 / 异常 / 待补）与订单池**只统计当天**，地图自动缩放到当天可排点位，右侧「当日车次」只列当天的草案。
- 切日时若已勾选的票不属于新日期，会自动移出选择并作废已算路线，避免"右栏有站、左栏没有票"。

### 数据口径
- 按订单**收货窗当地日期**（`window_start` 前 10 位）归档，与派单计划的取数口径一致。
- 没有收货窗的订单（如经站待入站）不进入任何单日视图，只在「全部日期」下可见。

### 改动
`v13/dispatch-map.js`（新增 `dayFilter` 状态、`dates()` 渲染、`accepts()` 前置过滤、切日清理已选、`dayPick` 日期输入处理）、`v13/dispatch-shell.css`（交付日条样式）。
